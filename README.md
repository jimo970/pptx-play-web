# Deckline PPTX Player

Deckline opens `.pptx` files in the browser. The selected file is read locally with JSZip, and archive/XML parsing runs in a module Worker; this app has no upload API.

## Run locally

```sh
npm install
npm run dev
```

Use `npm run typecheck` and `npm run build` before shipping.

With the development server on port 3000, `npm run verify:animation` runs the click-build browser check in local Edge or Chrome. Set `DECKLINE_BROWSER` when the browser is installed elsewhere.

## Current compatibility

The main stage, Speaker View, and the second display share slide transitions and a single resolved choice for randomized transitions. The projector catches up to the transition start time when its message arrives, and a newly opened preview does not replay a transition that has already finished.

Paragraph- and character-range `slide(fromLeft/fromRight/fromTop/fromBottom)` animations move their selected text from the matching stage edge, using the full-stage travel distance already used for object slide effects.

Rendering uses a DOM slide stage and CSS sizing from OOXML EMUs. Visual fidelity depends on browser fonts and Office features not yet covered by the matrix. Behavior-level timing and parent-time-container `p:cTn` `accel`/`decel`/`spd`/`autoRev` and repeat values affect animation progress, child start offsets, and after-effect scheduling. Negative parent speed reverses the group clock; `autoRev` plays it forward and back; finite-duration parent containers can repeat indefinitely. Overlong timing, timed media, and child-overflowing timing remain unapplied with a warning.

Main and interactive sequences accept the OOXML `withGroup` and `afterGroup` timing node types as group-level equivalents of `withEffect` and `afterEffect`; an `afterGroup` action waits for the longest preceding action in its current step ([Microsoft TimeNodeValues](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.timenodevalues?view=openxml-3.0.1)).

Animation parsing discovers nested `p:cTn` nodes carrying `presetClass` and reads their recognized child behavior elements through the existing parsers. It does not infer visual effects from `presetID`; unsupported child behaviors keep the normal warning/fallback behavior ([Microsoft CommonTimeNode.PresetClass](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.commontimenode.presetclass?view=openxml-3.0.1)).

Layout-origin motion paths honor `pathEditMode="relative"` and `pathEditMode="fixed"`, plus `rAng` rotation around `rCtr`. Parent-origin motion paths on grouped objects apply the accumulated DrawingML group transform. Motion-path formulas support arithmetic, deterministic math functions, `#ppt_x`, `#ppt_y`, `#ppt_w`, `#ppt_h`, and progress-dependent `$` values. Dynamic paths use at most 900 intervals (901 endpoint-inclusive samples); long animations warn when sampling is capped, and other variables or invalid formulas are skipped with a warning. Cross-checking grouped paths against PowerPoint remains pending.

Positive `p:cTn@spd` values scale behavior duration, repeat duration, and absolute iteration intervals; negative values reverse playback at the same speed magnitude. Zero and invalid speeds fall back to normal speed with a warning.

Numeric opacity animations also read up to 256 `p:tavLst` keypoints with `p:fltVal` or numeric `p:strVal`, interpolated linearly or stepped in discrete mode. Linear `p:tav/@fmla` formulas for `style.opacity`, `fill.opacity`, `stroke.opacity`, and `shadow.opacity` are sampled at up to 60 Hz and applied through the existing supported object and text-range paths; solid fills/strokes and existing shadows keep the same target restrictions as their numeric opacity animations. Other calculation modes, `rand`, unsupported variables, and out-of-range samples are skipped with a warning. Text-range formula rendering still needs visual calibration against Office/WPS. Microsoft lists these opacity properties in [MS-OE376 `tav`](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/981b17ff-5594-42cf-ad8d-7cb39e653afa).

Generic numeric `style.fontWeight` animations support explicit `from`/`to` values and up to 256 linear or discrete `p:tavLst` keypoints. Rendering follows CSS numeric font weights; available font faces may map intermediate weights to their nearest supported face. The supported target is listed in [Microsoft MS-OE376 `tav`](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/981b17ff-5594-42cf-ad8d-7cb39e653afa).

Discrete generic `p:anim` supports the documented string values for `style.fontStyle` (`none`, `normal`, `italic`), `style.textDecorationUnderline` and `style.textDecorationLineThrough` (`false`, `true`), `style.textTransform` (`none`, `normal`, `sub`, `super`), `style.textEffectOutline` (`false`, `true`), `style.textEffectEmboss` (`none`, `normal`, `emboss`), and `style.textShadow` (`none`, `normal`, `auto`) through direct `from`/`to` values or `p:tavLst` keyframes; text-shadow and emboss presets are also supported by `p:set`. Text transforms map to CSS baseline, subscript, or superscript alignment. Outline animation toggles the existing parsed `a:rPr/a:ln` run outlines and is limited to whole text frames where every non-empty run has a complete outline. Text-shadow animation hides the existing shadow for `none` and restores each run's parsed static shadow for `normal` or `auto`; it is limited to whole text frames where every non-empty run has a static shadow. Text-emboss animation uses paired CSS drop shadows as an approximation; lighting and bevel depth may differ from Office. Outline and text-shadow animations targeting unsupported text ranges or missing static styles are skipped with a warning. Linear interpolation and formula values for these categorical properties are skipped with a warning, following the [Microsoft MS-OE376 `to` value documentation](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/7b427ccc-3a1f-418b-821f-d78f7aed51c5) and the [Open XML run outline definition](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.runproperties?view=openxml-3.0.1).

Static DrawingML `a:rPr/@strike` accepts `noStrike`, `sngStrike`, or `dblStrike`; `dblStrike` maps to CSS double text-decoration. DrawingML `a:rPr/@u` maps `dbl`, `dotted`, `dash`, and `wavy` to their CSS line styles; `words`, heavy variants, and mixed underline/strike styles are approximated with a visible warning because CSS applies one style to all decorations from a text run. References: Microsoft [`TextStrikeValues`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.textstrikevalues?view=openxml-3.0.1), [`TextUnderlineValues`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.textunderlinevalues?view=openxml-3.0.1), and [CSS Text Decoration Level 3](https://www.w3.org/TR/css-text-decor-3/).

`p:set` applies those same text-style string values immediately to whole text frames or validated paragraph/character ranges, following Microsoft's [set behavior](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/7d6aef67-5dbc-456c-bcf5-f08011bbf5bf). Outline `p:set` is limited to whole text frames and uses the same existing-outline requirement when enabling.

Generic `style.visibility` `p:anim` supports whole-object and validated paragraph/character-range targets with discrete `visible`/`hidden` `from`/`to` values and string `p:tavLst` keyframes. Linear interpolation and formulas are skipped with warnings, following Microsoft's [`to` value documentation](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/7b427ccc-3a1f-418b-821f-d78f7aed51c5) and [`p:txEl` text-target definition](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.textelement?view=openxml-3.0.1).

Whole-picture `imageData.grayscale` `p:anim` supports discrete `false`/`true` `from`/`to` values, string `p:tavLst` keyframes, and `p:set`. Rendering uses the browser's CSS grayscale filter; unsupported targets, formulas, and interpolation modes are skipped with a warning, following Microsoft's [`to` value documentation](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/7b427ccc-3a1f-418b-821f-d78f7aed51c5) and [`tav` formula-variable list](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/981b17ff-5594-42cf-ad8d-7cb39e653afa).

Whole-picture `imageData.cropLeft`/`cropTop`/`cropRight`/`cropBottom` supports linear `from`/`to`, linear or discrete numeric `p:tavLst` keyframes, and `p:set`. Rendering reuses the existing `a:srcRect` image sizing and offset model. This subset accepts crop fractions in `[0, 1)` when opposing edges leave visible image content; formulas, negative/out-of-range values, and text-range targets are skipped with a warning, following Microsoft's [`tav` attribute list](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/981b17ff-5594-42cf-ad8d-7cb39e653afa), [`imagedata` fraction definition](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/7e506612-7a40-4d4e-95f4-e1f36173fe14), and [`ST_Fraction`](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/7cfc026d-b20e-4c2e-8c17-6a8460a7ed14).

Whole-picture `imageData.gain`, `imageData.blacklevel` (also accepting Microsoft's `blackleve` spelling in the animation variable list), and `imageData.gamma` support linear `from`/`to`, linear or discrete numeric `p:tavLst` keyframes, and `p:set`. The SVG `feComponentTransfer` renderer maps gain to contrast around the midpoint, blacklevel to a brightness offset, and gamma to exponent `1 / gamma` in sRGB. Microsoft documents these image properties and their contrast/brightness behavior; the exact SVG mapping is an approximation and still needs screenshot calibration against PowerPoint/WPS. Formula values, invalid ranges, and text-range targets are skipped with a warning. References: [MS-OE376 `tav`](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/981b17ff-5594-42cf-ad8d-7cb39e653afa), [MS-OE376 `imagedata`](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/7e506612-7a40-4d4e-95f4-e1f36173fe14), [Microsoft VML gain](https://learn.microsoft.com/en-us/windows/win32/vml/msdn-online-vml-gain-attribute), [Microsoft VML gamma](https://learn.microsoft.com/en-us/windows/win32/vml/msdn-online-vml-gamma-attribute), and [SVG `feComponentTransfer`](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/feComponentTransfer).

Linear `style.opacity`, `style.fontSize`, `style.fontWeight`, and `stroke.weight` keyframes may use `p:tav/@fmla`; formulas are pre-sampled at up to 60 Hz and support `$`, the matching target-property variable, `#ppt_x/y/w/h`, and deterministic math functions. The renderer applies each formula to the linearly interpolated numeric keyframe track, an interpretation inferred from Microsoft's formula and keyframe examples; formula-mode interpolation, `rand`, unsupported variables, and out-of-range values are skipped with a warning. Microsoft lists these properties among the allowed formula variables in [MS-OE376 `tav`](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/981b17ff-5594-42cf-ad8d-7cb39e653afa).

Numeric `stroke.weight` animations use EMU widths capped at 100,000,000 EMU. Direct `from`/`to`, linear or discrete numeric `p:tavLst` keyframes, `p:set`, and linear formula keyframes are supported for whole-shape and line targets; unsupported formula variables or sampled widths outside the cap are skipped with a warning. The formula allow-list includes `stroke.weight` per [MS-OE376 `tav`](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/981b17ff-5594-42cf-ad8d-7cb39e653afa).

`p:iterate` by letter or word also applies to generic numeric `style.opacity` and `style.fontWeight` animations and discrete text-style animations, in addition to text fade, font size, and color. Letter and word boundaries follow the browser's `Intl.Segmenter`; Microsoft's [`Iterate.Type`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.iterate.type?view=openxml-3.0.1) defines those iteration targets.

Discrete `style.fontFamily` animation accepts a single font name of up to 128 Unicode letters, numbers, spaces, dots, underscores, or hyphens. It supports `p:anim` direct `from`/`to` values, discrete `p:tavLst` string keyframes, `p:set`, and letter/word iteration. Formula values and linear interpolation are skipped with a warning; Microsoft documents the attribute name in [`AttributeName`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.attributename?view=openxml-3.0.1) and the formula variable in [MS-OE376 `tav`](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/981b17ff-5594-42cf-ad8d-7cb39e653afa).

Value-axis major gridlines render only when the source axis includes `c:majorGridlines`.

Bar/line/area combination charts preserve each chart group's `c:axId` references and render up to two value axes; combinations outside bar/line/area chart groups and axes beyond the first two are simplified with warnings ([Microsoft `BarChart`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.barchart?view=openxml-3.0.1), [`LineChart`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.linechart?view=openxml-3.0.1), [`AreaChart`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.areachart?view=openxml-3.0.1), [`AxisId`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.axisid?view=openxml-3.0.1)).

Radar charts read cached `c:cat`/`c:val` values and support the OOXML `standard`, `marker`, and `filled` styles with numeric value rings and category spokes from `c:majorGridlines` ([Microsoft `RadarChart`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.radarchart?view=openxml-3.0.1), [`RadarStyle`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.radarstyle?view=openxml-3.0.1)). Filled areas use a fixed translucent fill; non-circle markers are approximated as circles, and incomplete series keep open line segments without a fill.

Stock charts use the Microsoft documented HLC or OHLC price-series order and render high-low range lines, opening/closing ticks, cached close labels, optional drop lines, and `c:upDownBars` fills. Volume-HLC and volume-OHLC combinations also render one column volume series on its referenced secondary value axis when it shares the stock chart's category axis; other mixed chart layouts are reported as simplified. Detailed stock line/bar styling remains limited ([Microsoft stock chart types and series order](https://support.microsoft.com/en-us/excel/available-chart-types-in-office), [Microsoft `StockChart`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.stockchart?view=openxml-3.0.1), [Microsoft `AxisId`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.axisid?view=openxml-3.0.1), [`UpDownBars`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.updownbars?view=openxml-2.20.0)).
