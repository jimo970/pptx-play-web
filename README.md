# Deckline PPTX Player

Deckline opens `.pptx` files in the browser. The selected file is read locally with JSZip, and archive/XML parsing runs in a module Worker; this app has no upload API.

On touch screens, swipe to change slides and pinch to zoom. Once zoomed in, drag with one finger to pan; changing slides or returning to 100% resets the pan.

## Run locally

```sh
npm install
npm run dev
```

Use `npm run typecheck` and `npm run build` before shipping.

With the development server on port 3000, `npm run verify:animation` runs the click-build browser check in local Edge or Chrome. Set `DECKLINE_BROWSER` when the browser is installed elsewhere.

Set `DECKLINE_VERIFY_SHADOW_OFFSET=1` with that command to run the focused `shadow.offset.x/y` `p:anim` and `p:set` fixture.

For exported Office/WPS animation fixtures, capture a build with `DECKLINE_INPUT_PPTX`, `DECKLINE_CAPTURE_ONLY=1`, `DECKLINE_CAPTURE_SLIDE_NUMBER`, `DECKLINE_CAPTURE_ANIMATION_MS`, and `DECKLINE_CAPTURE_SLIDE_PATH`. A positive animation delay starts the first build click; at `0`, capture stays before the click unless `DECKLINE_CAPTURE_START_ANIMATION=1` is set. The adjacent PNG JSON records whether playback was triggered, sampled text transforms, warnings, and screenshot completion time; these timestamps expose capture drift and are not frame synchronization with native Office playback.

For short animation segments, `DECKLINE_CAPTURE_ANIMATION_CLOCK=controlled` holds the test page's `performance.now()` at the requested build time while real animation frames flush the rendered DOM. The capture records the controlled time and actual wall time separately and restores the clock after the screenshot. This validates property values at a fixed timeline position; it does not measure real-time frame cadence.

On Windows, `scripts/create-office-animation-fixture.ps1 -OutputDirectory <new-directory>` creates ten native by-letter animation slides by default, static PNG exports, and application metadata using Office COM automation. `-Suite Word`, `-Suite Motion`, and `-Suite CommonPresets` create five word effects, fourteen motion/exit cases, and seventeen common presets. `-ApplicationProgId PowerPoint.Application` selects that COM registration; inspect the recorded executable identity because WPS can register the same name. To generate with installed Microsoft Office, pass `-ApplicationProgId PowerPoint.Application.16 -ApplicationExecutablePath <POWERPNT.EXE>`; the script launches that executable hidden and verifies the COM connection path before exporting. Both WPS 12.1.0.29161 and Microsoft PowerPoint 16.0.19127.20860 Motion fixtures have been exercised locally.

`-Suite Motion` exercises fourteen fly, bounce, spin, grow/shrink, turn, blast, random, vertical-grow, swivel, swish, faded-swivel, and text-exit cases. Set `DECKLINE_OFFICE_ANIMATION_FIXTURE` to the generated PPTX and `DECKLINE_OFFICE_ANIMATION_EVIDENCE` to a new directory, then run `node scripts/verify-office-animation-playback.mjs` against the player. The verifier checks exported timing metadata and captures thirty browser checkpoints with transforms, opacity, timing, warnings, and a fixture SHA-256. Its controlled clock covers Bounce's four vertical legs and eight landing scale tracks, including the 26ms compression segments. WPS 12.1.0.29161 exports covering 98 checkpoints were checked in Edge; Microsoft PowerPoint 16.0.19127.20860 Motion exports covering 30 checkpoints and CommonPresets exports covering 38 checkpoints were also checked. The full animation suite passed in both Edge and Chrome. Random Effects files that omit the selected variant derive the fallback duration from the paired visibility restore so the effect remains visible through playback. These checks verify browser playback of exported OOXML tracks; native Office/WPS frame pixel comparisons remain pending.

## Current compatibility

Generic `p:anim` numeric actions support `ScaleX` and `ScaleY`, including linear or discrete `p:tav` keyframes and sampled linear formulas ([Microsoft `attrName`](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/baf99b7b-b2a7-44bb-a501-f6147d6c7123), [`tav`](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/981b17ff-5594-42cf-ad8d-7cb39e653afa)). Scale factors outside 0–10 are skipped.

Numeric `ppt_w`/`ppt_h` animations also support direct values, static shape-size expressions such as `#ppt_w`, linear/discrete keyframes, and sampled linear keyframe formulas. Width and height tracks become independent scale axes, including text ranges and letter/word iteration; signed values from -10 to 10 times the saved dimension preserve Swivel's axis reflections. WPS value expressions may omit the `#` prefix, and empty `fmla` attributes are treated as absent, as in the exported zoom/fly exits. A WPS 12.1.0.29161 export uses these tracks for Zoom without `animEffect`; fixtures cover both axes, staggered letters, visibility and fade composition, and the final saved size. Native WPS animation-frame and PowerPoint visual comparisons remain pending.

Geometry formula variables retain the saved shape properties: `ppt_x`/`ppt_y` use its center and `ppt_w`/`ppt_h` its dimensions, including the affine parent transform. Fixed and parent-origin motion paths anchor that center. This follows [LibreOffice's shape-bound formula mapping](https://github.com/LibreOffice/core/blob/master/slideshow/source/engine/smilfunctionparser.cxx). Grouped parent-origin paths now have a WPS-exported OOXML regression case; native Office/WPS frame calibration remains pending.

Separate source time nodes are retained when multiple scale, rotation, color, opacity, font, or motion behaviors target the same object/property. This preserves sequential animation segments within one effect, including Bounce's landing tracks. `animScale` to-only tracks follow Microsoft's documented `(0, 0)` starting value; native WPS squash/recovery frame calibration remains pending ([Microsoft `animScale` behavior](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/358c6de3-2cd7-459b-8eb9-b90f3721fd12)). Fixed motion-path rotations use the shape center when rotating around `rCtr`.

`p:tmPct` iteration uses the containing effect's duration for all supported child tracks, so an instantaneous visibility set and its Zoom size tracks begin together for each letter. Intervals above 100% are accepted through PowerPoint's documented 2,147,483,625 limit ([Microsoft `TimePercentage`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.timepercentage?view=openxml-3.0.1), [`tmPct` limits](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/2a0ee2cf-f017-44a9-a15f-165e018e750f)). The focused `DECKLINE_VERIFY_ITERATED_TEXT_EFFECTS=1` run also accepts `DECKLINE_VERIFY_LARGE_ITERATION_INTERVAL=1` to verify a 200% interval.

`p:cTn@tmFilter` supports complete time graphs from `0,0` to `1,1` with up to 256 control points. Input times must increase; output progress may reverse between points. Piecewise interpolation remaps action or finite parent clocks, and inverse clock lookup selects the earliest crossing on a reversing curve. Malformed or unsupported graphs warn and use unfiltered timing. WPS Bounce supplies these curves for its horizontal and vertical legs ([Microsoft `Progress`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.progress?view=openxml-3.0.1)). Visibility sets change visibility independently of fade opacity. Combined parent time filters and acceleration/deceleration have mathematical coverage; native visual calibration remains pending.

Custom/preset paths retain `lighten`, `lightenLess`, `darken`, and `darkenLess` fill modes ([Microsoft PathFillModeValues](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.pathfillmodevalues?view=openxml-3.0.1)). Solid colors, gradient stops, and animated fill colors use the 40%/20% white or black blends from [LibreOffice's implementation](https://github.com/LibreOffice/core/blob/master/svx/source/customshapes/EnhancedCustomShape2d.cxx), preserving alpha and leaving outlines unchanged. Office/WPS calibration for these path-fill modes remains pending.

Solid-color DrawingML `tint`, `shade`, `lumMod`, `lumOff`, `gamma`, `invGamma`, and `gray` transforms are checked against a PowerPoint export fixture. Microsoft's Open XML references define their roles ([tint](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.tint?view=openxml-3.0.1), [shade](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.shade?view=openxml-3.0.1), [luminance modulation](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.luminancemodulation?view=openxml-3.0.1), [luminance offset](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.luminanceoffset?view=openxml-3.0.1), [gamma](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.gamma?view=openxml-3.0.1), [inverse gamma](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.inversegamma?view=openxml-3.0.1), [gray](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.gray?view=openxml-3.0.1)); general Office/WPS color parity remains unverified.

DrawingML `a:arcTo` angles intersect the ellipse before path-coordinate scaling. The shared custom/preset path parser accepts start and sweep angles throughout the signed 32-bit DrawingML angle range, splits sweeps into segments of at most half a turn, and preserves the pen point for zero sweeps ([Microsoft ArcTo](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.arcto?view=openxml-3.0.1), [ECMA-376](https://ecma-international.org/publications-and-standards/standards/ecma-376/)). Browser regression fixtures cover off-axis elliptical starts, positive and negative multi-turn sweeps, and non-uniform path coordinates. A PowerPoint screenshot comparison covers six representative cases; rendered path bounds differ by at most 1 pixel at 1280×720, while antialiasing differs between renderers. WPS screenshot calibration remains pending.

Cached zero and negative values are omitted with a warning while logarithmic scaling is active because logarithmic scales require positive values ([Microsoft `LogBase`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.logbase?view=openxml-3.0.1), [Microsoft logarithmic axis guidance](https://support.microsoft.com/en-us/office/change-the-scale-of-the-vertical-value-axis-in-a-chart)).

Chart data-label text properties from `c:txPr` cascade from chart group to series to point; run-level character spacing from `a:rPr/@spc`, baseline shifts from `a:rPr/@baseline`, underline color and solid stroke width, and single/double strikethrough are rendered ([Microsoft `RunProperties`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.runproperties?view=openxml-3.0.1), [Microsoft baseline behavior](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/4823e093-d57b-4b05-91a6-4858174d8b64), [MS-OI29500 `ST_TextSpacingPoint`](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/b6aeb5af-90ac-41dc-8964-f7ba99ed5181), [`TextUnderlineValues`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.textunderlinevalues?view=openxml-3.0.1), [`UnderlineFill`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.underlinefill?view=openxml-3.0.1), [`Underline`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.underline?view=openxml-3.0.1)). Independent styling for simultaneous underline and strikethrough, non-solid underline paints/strokes, paragraph spacing/layout, outlines, and effects remain simplified.

Static picture `a:grayscl` effects are read from the `a:blip` node and rendered with the same grayscale filter used by `imageData.grayscale` animations ([Microsoft `Grayscale`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.grayscale?view=openxml-3.0.1)).

Pie/doughnut `c:showLeaderLines` draws three-segment connectors for `outEnd` data labels; point settings override series/chart settings. Custom leader-line `spPr` keeps the default browser appearance and emits a warning ([Microsoft `ShowLeaderLines`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.showleaderlines?view=openxml-3.0.1)).

Exception to the detailed `Object animation` timing limit above: timed-media time-node `begin`/`end` aliases and target `onBegin`/`onEnd` conditions are fixture verified when `p:tn/@val` references a parsed main-sequence media action; other time-node references remain unsupported.

Main and interactive-sequence `p:subTnLst` entries support `masterRel="sameClick"`, `"lastClick"`, and `"nextClick"`; `lastClick` binds to the previous click step. Nested `masterRel` values remain unsupported.

Generic `p:anim` supports `style.rotation` with signed DrawingML angle values, linear/discrete `p:tav` keyframes, and sampled formulas using the supported numeric expression subset, including `rand(x)`. Random keyframe samples are fixed when the slide model is parsed and replay unchanged on repeat. Microsoft lists `style.rotation` as an allowed animation target; its 60,000-units-per-degree conversion follows the documented DrawingML rotation angle unit ([`AttributeName`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.attributename?view=openxml-3.0.1), [`AnimateRotation`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.animaterotation?view=openxml-3.0.1), [`tav` formula syntax and `rand(x)`](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/981b17ff-5594-42cf-ad8d-7cb39e653afa)).

Presentation-wide `p:showPr/@showNarration` suppresses only `p:audio` actions marked with `@isNarration`; ordinary audio and video playback remain enabled ([Microsoft `ShowNarration`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.showproperties.shownarration?view=openxml-3.0.1), [MS-OE376 `audio`](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/23369f6c-a587-43fc-888e-cb254558f56c)).
