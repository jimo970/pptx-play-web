# Deckline PPTX Player

Deckline opens `.pptx` files in the browser. The selected file is read locally with JSZip, and archive/XML parsing runs in a module Worker; this app has no upload API.

## Run locally

```sh
npm install
npm run dev
```

Use `npm run typecheck` and `npm run build` before shipping.

With the development server on port 3000, `npm run verify:animation` runs the click-build browser check in local Edge or Chrome. Set `DECKLINE_BROWSER` when the browser is installed elsewhere.

## Current compatibility

The main stage, Speaker View, and the second display share slide transitions and a single resolved choice for randomized transitions. The projector catches up to the transition start time when its message arrives, and a newly opened preview does not replay a transition that has already finished.

The Office 2010 `p14:flip` transition uses a directional CSS 3D card rotation; duration is read from `p14:dur`, but motion has not been calibrated against PowerPoint screenshots.

The Office 2010 `p14:reveal` transition uses a directional paired slide movement and honors `thruBlk` with a black midpoint; this motion is also awaiting PowerPoint screenshot calibration.

The Office 2010 `p14:switch` transition uses a directional CSS 3D quarter-turn between slide planes; its motion is awaiting PowerPoint screenshot calibration.

The Office 2010 `p14:pan` transition uses paired directional movement in all eight side directions; motion is an approximation awaiting PowerPoint screenshot calibration.

The Office 2010 `p14:ripple` transition uses a direction-aware radial wavefront mask; the mask is an approximation awaiting PowerPoint screenshot calibration.

The Office 2010 `p14:glitter` transition uses directionally staggered diamond or hexagon tiles; tile geometry and timing are approximations awaiting PowerPoint screenshot calibration.

The Office 2013 `p15:prstTrans` parser accepts `fallOver`, `drape`, `curtains`, `wind`, `prestige`, `fracture`, `crush`, `peelOff`, `pageCurlDouble`, `pageCurlSingle`, `airplane`, and `origami`. These transitions use CSS 3D transforms and masks as visual approximations and still need screenshot calibration against PowerPoint ([Microsoft preset transition schema](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-pptx/56b22fd1-50b2-4a24-ab96-20a78cac7b06), [Office 2012 namespace schema](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-pptx/27d7324c-0a29-4475-a980-de020defb315)).

Rendering uses a DOM slide stage and CSS sizing from OOXML EMUs. Visual fidelity depends on browser fonts and Office features not yet covered by the matrix. Behavior-level timing and parent-time-container `p:cTn` `accel`/`decel`/`spd`/`autoRev` and repeat values affect animation progress, child start offsets, and after-effect scheduling. Negative parent speed reverses the group clock; `autoRev` plays it forward and back; finite-duration parent containers can repeat indefinitely. Overlong timing, timed media, and child-overflowing timing remain unapplied with a warning.

Main and interactive sequences accept the OOXML `withGroup` and `afterGroup` timing node types as group-level equivalents of `withEffect` and `afterEffect`; an `afterGroup` action waits for the longest preceding action in its current step ([Microsoft TimeNodeValues](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.timenodevalues?view=openxml-3.0.1)).

Animation parsing discovers nested `p:cTn` nodes carrying `presetClass` and reads their recognized child behavior elements through the existing parsers. It does not infer visual effects from `presetID`; unsupported child behaviors keep the normal warning/fallback behavior ([Microsoft CommonTimeNode.PresetClass](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.commontimenode.presetclass?view=openxml-3.0.1)).

Layout-origin motion paths honor `pathEditMode="relative"` and `pathEditMode="fixed"`, plus `rAng` rotation around `rCtr`. Parent-origin motion paths on grouped objects apply the accumulated DrawingML group transform. Motion-path formulas support arithmetic, deterministic math functions, `#ppt_x`, `#ppt_y`, `#ppt_w`, `#ppt_h`, and progress-dependent `$` values. Dynamic paths use at most 900 intervals (901 endpoint-inclusive samples); long animations warn when sampling is capped, and other variables or invalid formulas are skipped with a warning. Cross-checking grouped paths against PowerPoint remains pending.

Positive `p:cTn@spd` values scale behavior duration, repeat duration, and absolute iteration intervals; negative values reverse playback at the same speed magnitude. Zero and invalid speeds fall back to normal speed with a warning.

Numeric opacity animations also read up to 256 `p:tavLst` keypoints with `p:fltVal` or numeric `p:strVal`, interpolated linearly or stepped in discrete mode; formula values and other calculation modes remain unsupported.

Generic numeric `style.fontWeight` animations support explicit `from`/`to` values and up to 256 linear or discrete `p:tavLst` keypoints. Rendering follows CSS numeric font weights; available font faces may map intermediate weights to their nearest supported face. The supported target is listed in [Microsoft MS-OE376 `tav`](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/981b17ff-5594-42cf-ad8d-7cb39e653afa).

Value-axis major gridlines render only when the source axis includes `c:majorGridlines`.
