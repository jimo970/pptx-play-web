# Deckline PPTX Player

Deckline opens `.pptx` files in the browser. The selected file is read locally with JSZip, and archive/XML parsing runs in a module Worker; this app has no upload API.

On touch screens, swipe to change slides and pinch to zoom. Once zoomed in, drag with one finger to pan; changing slides or returning to 100% resets the pan.

## Run locally

```sh
npm install
npm run dev
```

Use `npm run typecheck` and `npm run build` before shipping.

With the development server on port 3000, `npm run verify:animation` runs the click-build browser check in local Edge or Chrome. Set `DECKLINE_BROWSER` when the browser is installed elsewhere.

## Current compatibility

Custom/preset paths retain `lighten`, `lightenLess`, `darken`, and `darkenLess` fill modes ([Microsoft PathFillModeValues](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.pathfillmodevalues?view=openxml-3.0.1)). Solid colors, gradient stops, and animated fill colors use the 40%/20% white or black blends from [LibreOffice's implementation](https://github.com/LibreOffice/core/blob/master/svx/source/customshapes/EnhancedCustomShape2d.cxx), preserving alpha and leaving outlines unchanged. Office/WPS color calibration remains pending.

DrawingML `a:arcTo` angles intersect the ellipse before path-coordinate scaling. The shared custom/preset path parser supports positive and negative sweeps up to a full turn, splits arcs into segments of at most half a turn, and preserves the pen point for zero sweeps ([Microsoft ArcTo](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.arcto?view=openxml-3.0.1), [Apache POI angle conversion](https://github.com/apache/poi/blob/trunk/poi/src/main/java/org/apache/poi/sl/draw/geom/ArcToCommand.java)). Browser regression fixtures cover off-axis elliptical starts, signed and full-turn sweeps, and non-uniform path coordinates; Office/WPS screenshot calibration remains pending.

Theme styles propagate through placeholders, master/layout decoration, groups, and cached SmartArt; the focused notes check covers solid/reference fills and override precedence. Theme effect references render supported outer and inner shadows plus glow approximations.

Speaker notes and slide text share script classification and font-name handling. Mixed runs select Latin, East Asian, and complex-script fonts per segment; combining marks follow the preceding script and notes retain the run's language attribute. The focused notes check verifies requested CSS families for Latin/Chinese/Arabic text; installed-font glyph fidelity and metrics still require Office/WPS calibration.

Color `comp`, `inv`, and `alphaInv` transforms execute without a `val` attribute and preserve document order. Complement rotates hue while retaining saturation/lightness; inverse reverses RGB components; alpha inverse reverses opacity ([Microsoft complement](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.complement?view=openxml-3.0.1), [inverse](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.inverse?view=openxml-3.0.1)). The focused `DECKLINE_VERIFY_NOTES=1` check covers gray/complement behavior, repeated inverse, opacity boundaries, and mixed transforms. Image/effect-container `alphaInv` is not covered by this color-parser implementation.

RGB channel transforms (`red`, `green`, `blue`, and their `Mod`/`Off` variants) change the selected component while preserving the other channels and alpha. Integer/percentage values, signed offsets, and per-operation clamping are supported ([Microsoft channel modulation](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.redmodulation?view=openxml-3.0.1)). The focused `DECKLINE_VERIFY_NOTES=1` check covers all nine variants, alpha preservation, clamp order, and interleaved RGB/HSL transforms.

DrawingML `hue`/`hueMod`/`hueOff`, `sat`/`satMod`/`satOff`, and `lum`/`lumMod`/`lumOff` color transforms execute in document order. Hue uses angle units for absolute/offset values and percentages for modulation; saturation/lightness clamp after each operation. Consecutive HSL transforms retain hue through zero saturation ([Microsoft color transforms](https://learn.microsoft.com/en-us/previous-versions/office/jj603569(v=office.15))). The focused `DECKLINE_VERIFY_NOTES=1` check covers all nine operations, negative hue wrap, and saturation clamp/order.

HSL saturation/lightness accept integer and percentage-string values. Linear scRGB channels convert to browser sRGB, including the low-intensity linear segment; 50% scRGB gray resolves to `#bcbcbc` ([Microsoft scRGB model](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.rgbcolormodelpercentage?view=openxml-3.0.1), [W3C conversion](https://www.w3.org/TR/css-color-4/#color-conversion-code)). Theme slots share the same color parser. The focused `DECKLINE_VERIFY_NOTES=1` check covers direct HSL/scRGB fills, alpha, and theme references.

Color transforms accept both integer values (100000 = 100%) and percentage strings. Tint follows DrawingML semantics: 10% retains 10% of the input color and mixes in 90% white. Alpha modulation/offset clamps after each transform; luminance modulation and offset support signed percentages ([Microsoft percentage values](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/ff18a37e-9bd7-4338-9c37-1e285b5a5dd2), [OOXML primer](https://download.microsoft.com/download/e/1/4/e14fb96f-83b8-4a2a-84db-7fa8acbe061a/Office%20Open%20XML%20Part%203%20-%20Primer.pdf)). The focused `DECKLINE_VERIFY_NOTES=1` check also covers color percentage equivalence, tint boundaries, and ordered transforms.

The main stage, Speaker View, and the second display share slide transitions and a single resolved choice for randomized transitions. The projector catches up to the transition start time when its message arrives, and a newly opened preview does not replay a transition that has already finished. Pen/highlighter strokes and the live laser point are mirrored to the second display; slide changes send a fresh annotation snapshot.

Chart category/date labels format common Excel date/time number codes using the chart's `date1904` flag when present. Common chart number formats preserve quoted or escaped literal prefixes and suffixes, including currency symbols and units; support thousand-scaling commas and scientific notation with `E+`/`E-` exponent codes ([Microsoft custom number formats](https://support.microsoft.com/en-us/excel/review-guidelines-for-customizing-a-number-format)). Mixed and improper fraction masks support one-to-three-digit variable denominators and fixed denominators up to six digits, using nearest-fraction rounding while preserving a fixed denominator ([Microsoft fractions](https://support.microsoft.com/en-us/excel/display-numbers-as-fractions)). Discrete `style.fontFamily` animation accepts a single font name of up to 128 Unicode letters, numbers, spaces, dots, underscores, or hyphens. It supports `p:anim` direct `from`/`to` values, discrete `p:tavLst` string keyframes, `p:set`, and letter/word iteration. Formula values and linear interpolation are skipped with a warning; Microsoft documents the attribute name in [`AttributeName`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.attributename?view=openxml-3.0.1) and the formula variable in [MS-OE376 `tav`](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/981b17ff-5594-42cf-ad8d-7cb39e653afa).

Value-axis major gridlines render only when the source axis includes `c:majorGridlines`.

Bar/line/area combination charts preserve each chart group's `c:axId` references and render up to two value axes; combinations outside bar/line/area chart groups and axes beyond the first two are simplified with warnings ([Microsoft `BarChart`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.barchart?view=openxml-3.0.1), [`LineChart`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.linechart?view=openxml-3.0.1), [`AreaChart`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.areachart?view=openxml-3.0.1), [`AxisId`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.axisid?view=openxml-3.0.1)).

Radar charts read cached `c:cat`/`c:val` values and support the OOXML `standard`, `marker`, and `filled` styles with numeric value rings and category spokes from `c:majorGridlines` ([Microsoft `RadarChart`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.radarchart?view=openxml-3.0.1), [`RadarStyle`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.radarstyle?view=openxml-3.0.1)). Series and point marker symbols listed above render as vector shapes. Filled areas use a fixed translucent fill, and incomplete series keep open line segments without a fill.

Stock charts use the Microsoft documented HLC or OHLC price-series order and render high-low range lines, opening/closing ticks, cached close labels, optional drop lines, and `c:upDownBars` fills. Volume-HLC and volume-OHLC combinations also render one column volume series on its referenced secondary value axis when it shares the stock chart's category axis; other mixed chart layouts are reported as simplified. Detailed stock line/bar styling remains limited ([Microsoft stock chart types and series order](https://support.microsoft.com/en-us/excel/available-chart-types-in-office), [Microsoft `StockChart`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.stockchart?view=openxml-3.0.1), [Microsoft `AxisId`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.axisid?view=openxml-3.0.1), [`UpDownBars`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.updownbars?view=openxml-2.20.0)).

Numeric value axes, including scatter and bubble X axes, honor valid `c:logBase` values with logarithmic coordinates and power-interval major ticks. An invalid or out-of-range base warns and falls back to linear scaling. Cached zero and negative values are omitted with a warning while logarithmic scaling is active because logarithmic scales require positive values ([Microsoft `LogBase`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.logbase?view=openxml-3.0.1), [Microsoft logarithmic axis guidance](https://support.microsoft.com/en-us/office/change-the-scale-of-the-vertical-value-axis-in-a-chart)).

Chart data-label text properties from `c:txPr` cascade from chart group to series to point; run-level character spacing from `a:rPr/@spc`, baseline shifts from `a:rPr/@baseline`, underline color and solid stroke width, and single/double strikethrough are rendered ([Microsoft `RunProperties`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.runproperties?view=openxml-3.0.1), [Microsoft baseline behavior](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/4823e093-d57b-4b05-91a6-4858174d8b64), [MS-OI29500 `ST_TextSpacingPoint`](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/b6aeb5af-90ac-41dc-8964-f7ba99ed5181), [`TextUnderlineValues`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.textunderlinevalues?view=openxml-3.0.1), [`UnderlineFill`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.underlinefill?view=openxml-3.0.1), [`Underline`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.underline?view=openxml-3.0.1)). Independent styling for simultaneous underline and strikethrough, non-solid underline paints/strokes, paragraph spacing/layout, outlines, and effects remain simplified.
